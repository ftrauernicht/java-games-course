# Kurs 5 – 2048

**Ziel:** das Schiebespiel, spielbar im Terminal. Vier Richtungen, die in
Wirklichkeit eine einzige Operation auf einem gedrehten Spielfeld sind, und eine
Verschmelzungsregel, die fast jeder im ersten Anlauf falsch macht.

Hier endet auch der Weg der Konsole, und das Kapitel sagt das offen, statt so zu
tun, als wäre es anders.

Setzt [Kurs 1](../../01-basics/de/00-einfuehrung.md) voraus und sonst nichts. Eine
fertige Fassung liegt in [`code/Game2048.java`](../code/Game2048.java).

## 🟢 Kern — Das Spiel, und der Name der Klasse

Ein Feld aus vier mal vier Plättchen. Jeder Zug schiebt alle Plättchen so weit, wie
sie in eine Richtung kommen. Zwei gleiche Zahlen, die aufeinandertreffen,
verschmelzen zu einem Plättchen mit dem doppelten Wert. Nach jedem Zug, der etwas
verändert hat, erscheint ein neues Plättchen auf einem freien Feld.

Fang die Datei an. Sie kann nicht `2048.java` heißen, denn ein Java-Name darf nicht
mit einer Ziffer beginnen. Die Klasse heißt also `Game2048` und die Datei
`Game2048.java`:

```java
import java.util.Scanner;

public class Game2048 {

    static final int SIZE = 4;

    public static void main(String[] args) {
    }
}
```

## 🟢 Kern — Zweidimensionale Arrays, kurz erklärt

*(Wenn du Kurs 2 oder Kurs 4 gemacht hast, überspring das und lies beim nächsten
Abschnitt weiter.)*

Kurs 1 hat dir ein Array gegeben: eine Reihe von Werten unter einem Namen. Ein
Spielfeld ist ein Array, dessen Werte selbst Arrays sind:

```java
int[][] board = new int[SIZE][SIZE];
```

`board[1][2]` ist Zeile 1, Spalte 2, und beide zählen ab 0. Der Typ ist `int`, weil
ein Feld eine Zahl enthält, und ein frisches `int`-Array ist voller Nullen. Die 0
kann also ohne jede Vorbereitung für „leer" stehen.

Das ganze Feld durchläuft man mit einer Schleife in einer Schleife:

```java
for (int row = 0; row < SIZE; row++) {
    for (int col = 0; col < SIZE; col++) {
        // board[row][col]
    }
}
```

Noch etwas, das dieses Kapitel benutzt: `board[row]` allein, ohne zweites
Klammerpaar, ist die ganze Zeile, und sie ist ein `int[]`. Das ist wichtig zu
wissen, denn ein Spielfeld ist in Wahrheit ein Array aus Zeilen, und einer Methode,
die mit einer Zeile arbeitet, kannst du `board[2]` direkt übergeben.

## 🟢 Kern — Ein Spielfeld ausgeben, dessen Zahlen wachsen

Plättchen beginnen bei 2 und können vierstellig werden, eine feste Breite hält die
Spalten also untereinander. Das `printf` aus Kurs 1 erledigt es:

```java
static void print(int[][] board) {
    System.out.println();
    for (int row = 0; row < SIZE; row++) {
        for (int col = 0; col < SIZE; col++) {
            if (board[row][col] == 0) {
                System.out.printf("%5s", ".");
            } else {
                System.out.printf("%5d", board[row][col]);
            }
        }
        System.out.println();
    }
    System.out.println();
}
```

```
    .    .    2    .
    .    4    .    .
    2    .    .    .
    .    .    .    .
```

`%5d` ist eine Zahl in einem fünf Zeichen breiten Feld, `%5s` dasselbe für Text.
Ohne die Breite wäre eine Zeile mit 2 und 1024 ausgefranst und unlesbar.

Ein neues Plättchen kommt auf ein zufälliges freies Feld und ist meistens eine 2:

```java
static void spawn(int[][] board) {
    while (true) {
        int row = (int) (Math.random() * SIZE);
        int col = (int) (Math.random() * SIZE);
        if (board[row][col] == 0) {
            board[row][col] = Math.random() < 0.9 ? 2 : 4;
            return;
        }
    }
}
```

So lange zu würfeln, bis man ein freies Feld trifft, geht in Ordnung, solange das
Feld überwiegend leer ist, und auf einem vollen Feld wird diese Methode nie
aufgerufen.

Leg zwei Plättchen hin und gib das Feld aus:

```java
int[][] board = new int[SIZE][SIZE];
spawn(board);
spawn(board);
print(board);
```

## 🟢 Kern — Einen Zug tippen, und die Enter-Taste im Weg

Im echten Spiel drückst du eine Pfeiltaste und das Feld bewegt sich sofort. Hier
tippst du einen Buchstaben und drückst Enter, und das ist keine Abkürzung. Java
kann aus einem Terminal überhaupt keinen einzelnen Tastendruck lesen. Das Terminal
sammelt erst eine ganze Zeile, bevor es irgendetwas herausgibt, und das JDK hat
keine Möglichkeit, es darum zu bitten, das zu lassen. Pfeiltasten sind noch
schlimmer: Sie kommen als mehrere Zeichen auf einmal an.

Also: `w`, `a`, `s`, `d`, und `q` zum Beenden, jeweils gefolgt von Enter.

```java
Scanner in = new Scanner(System.in);

System.out.print("Move (w/a/s/d, q to quit): ");
String line = in.nextLine().trim().toLowerCase();
```

`.toLowerCase()` sorgt dafür, dass ein versehentliches großes `W` trotzdem geht,
und `.trim()` verzeiht ein Leerzeichen. Das ist die Grenze, der die Kurse 6 und 7
entkommen, indem sie ein Fenster öffnen, wo eine Taste im Moment des Drucks
ankommt. Es lohnt sich zu wissen, welche der beiden die echte Einschränkung ist:
das Terminal, nicht Javas Fähigkeit, Spiele zu bauen.

## 🟢 Kernübung — Eine Zeile schieben

Alles in diesem Spiel passiert mit einer einzelnen Zeile, nach links geschoben.
Bekomm das richtig hin, und der Rest ist Buchhaltung.

```java
static int[] slideRowLeft(int[] row) {
    // dein Code hier -- die drei Schritte unten
}
```

1. **Zusammenschieben.** Lauf durch die Zeile und kopier jeden Wert ungleich 0 in
   ein neues Array, einen nach dem anderen ab Stelle 0. Lücken verschwinden, die
   Reihenfolge bleibt.
2. **Verschmelzen.** Lauf von links nach rechts durch das zusammengeschobene
   Array. Wo ein Wert gleich seinem Nachbarn und nicht 0 ist, verdopple den ersten,
   setz den zweiten auf 0, und **überspring den, den du gerade geleert hast**.
3. **Nochmal zusammenschieben.** Das Verschmelzen hinterlässt Löcher, also mach
   Schritt 1 ein zweites Mal und gib das Ergebnis zurück.

Schritt 2 ist die eigentliche Übung, und das Überspringen ist der Grund. Ein
Plättchen darf pro Zug höchstens einmal verschmelzen. Ohne das Überspringen fällt
eine Zeile aus vier Zweien zu einer einzelnen 8 zusammen, und das Spiel wird ein
anderes, viel leichteres.

Rechne diese Fälle auf Papier durch, bevor du irgendetwas schreibst:

```
2 2 2 2   wird   4 4 . .      (zwei getrennte Verschmelzungen, keine 8)
4 2 2 .   wird   4 4 . .      (die beiden 2 verschmelzen, die 4 bleibt)
2 2 4 .   wird   4 4 . .      (dasselbe Ergebnis, anderer Grund)
4 4 4 4   wird   8 8 . .
2 4 2 4   wird   2 4 2 4      (nichts verschmilzt, nichts bewegt sich)
```

Die dritte Zeile ist die, die Leute erwischt: Nachdem die beiden 2 zu einer 4
geworden sind, steht sie neben der vorhandenen 4, und sie darf **nicht** noch
einmal verschmelzen. Das ist dieselbe Regel wie in der ersten Zeile, von der
anderen Seite gesehen.

Teste deine Methode mit allen fünf Zeilen oben, bevor du dich ans Spielfeld
machst.

## 🟢 Kern — Vier Richtungen, eine Operation

„Links" hast du jetzt. Statt drei weitere Fassungen zu schreiben, dreh das
Spielfeld und benutz die, die du hast.

```java
static void rotateClockwise(int[][] board) {
    int[][] turned = new int[SIZE][SIZE];
    for (int row = 0; row < SIZE; row++) {
        for (int col = 0; col < SIZE; col++) {
            turned[col][SIZE - 1 - row] = board[row][col];
        }
    }
    for (int row = 0; row < SIZE; row++) {
        board[row] = turned[row];
    }
}
```

Das Feld an `(row, col)` landet bei `(col, SIZE - 1 - row)`. Nimm ein Blatt Papier
mit einem Buchstaben in jeder Ecke und dreh es eine Vierteldrehung, um dich davon
zu überzeugen.

Die letzte Schleife kopiert die Zeilen zurück in das Spielfeld, das übergeben
wurde, damit der Aufrufer die Änderung sieht. `board = turned` würde nur den
lokalen Namen auf das neue Feld richten und draußen nichts ändern, und das ist die
Grenze dessen, was „Arrays sind Verweise" dir kauft.

Ein Zug ist dann: drehen, jede Zeile nach links schieben, zurückdrehen.

```java
static void move(int[][] board, int rotations) {
    for (int i = 0; i < rotations; i++) {
        rotateClockwise(board);
    }

    for (int row = 0; row < SIZE; row++) {
        board[row] = slideRowLeft(board[row]);
    }

    for (int i = 0; i < (4 - rotations) % 4; i++) {
        rotateClockwise(board);
    }
}
```

Wie viele Drehungen zu welcher Richtung gehören, leitet man besser her, als es
auswendig zu lernen. Hier ist die Antwort zum Gegenprüfen: links ist 0, runter ist
1, rechts ist 2, hoch ist 3. Teste jede Richtung mit einem einzelnen Plättchen in
einer bekannten Ecke und schau, wo es landet.

Das `switch` aus Kurs 1 macht aus einem Buchstaben diese Zahl:

```java
int rotations = switch (line) {
    case "a" -> 0;
    case "s" -> 1;
    case "d" -> 2;
    case "w" -> 3;
    default -> -1;
};

if (rotations < 0) {
    System.out.println("Type w, a, s or d, or q to quit.");
    continue;
}
```

Das ist ein `switch`, das als Wert benutzt wird und nicht als Anweisung: Das Ganze
ergibt eine Zahl, und deshalb steht am Ende ein Semikolon. Die `-1` steht für
„keine Richtung", so wie Kurs 2 die 0 für „kein Feld" benutzt hat.

## 🟢 Kern — Ein Zug, der nichts verändert

Schieb zweimal nach links, und das zweite Mal passiert nichts. Erscheint trotzdem
ein neues Plättchen, bekommt der Spieler Gratisplättchen für einen Tastendruck,
der nichts bewegt hat, und das Feld füllt sich, ohne dass gespielt wurde.

Also vergleich vorher und nachher:

```java
int[][] before = copy(board);
move(board, rotations);

if (same(before, board)) {
    System.out.println("Nothing moves that way.");
    continue;
}

spawn(board);
```

`copy` und `same` sind beide eine Schleife in einer Schleife, eine schreibend und
eine vergleichend:

```java
static int[][] copy(int[][] board) {
    int[][] result = new int[SIZE][SIZE];
    for (int row = 0; row < SIZE; row++) {
        for (int col = 0; col < SIZE; col++) {
            result[row][col] = board[row][col];
        }
    }
    return result;
}
```

Warum nicht `int[][] before = board;`? Weil das ein Spielfeld mit zwei Namen ist,
und nach dem Zug zeigen beide Namen auf das bewegte Feld. Es bliebe nichts übrig,
womit man vergleichen könnte. Kurs 1 hat genau davor unter „Arrays sind Verweise"
gewarnt, und das hier ist die Stelle, an der das Vergessen ein Spiel erzeugt, das
stillschweigend schummelt.

`same` schreibst du selbst; es ist `copy` mit einem Vergleich statt einer Zuweisung
und einem frühen `return false`.

Jetzt die Schleife in `main`: ausgeben, lesen, umwandeln, ziehen, vergleichen,
neues Plättchen. Ergänze eine Prüfung auf ein volles Feld, um das Spiel zu beenden,
und du hast etwas Spielbares.

## 🟡 Optional — Ein Punktestand

Zähl den Wert jeder Verschmelzung zusammen und zeig die Summe. Verschmolzen wird
nur in `slideRowLeft`, und die gibt derzeit eine Zeile zurück und hat damit keinen
Platz für eine zweite Antwort. Entweder du führst einen Zähler außerhalb, oder du
gibst die Zeile zurück und rechnest den Punktestand getrennt. Entscheide dich für
eines und schreib in einen Kommentar, warum.

## 🟡 Optional — Mehrere Züge in einer Zeile

Ein Zug pro Enter ist mühsam. Nimm `wasd` als vier Züge in einer Zeile an, indem du
mit `charAt` aus Kurs 1 über die Zeichen läufst und jedes als eigenen Zug
behandelst.

Achte auf das Detail, das dabei sichtbar wird: Nach jedem Buchstaben musst du
prüfen, ob sich das Feld verändert hat und ob ein neues Plättchen kommt, genau wie
in der Fassung mit einem Zug.

## 🔴 Optional, echte Herausforderung — Richtiges Spielende

Die grüne Fassung endet, wenn das Feld voll ist. Das ist nicht die echte Regel. Ein
volles Feld ist weiter spielbar, solange zwei gleiche Plättchen nebeneinander
liegen, denn dieser Zug verschmilzt sie und macht ein Feld frei.

Schreib die echte Prüfung: Das Spiel ist vorbei, wenn es kein leeres Feld gibt
**und** keine zwei waagerecht oder senkrecht benachbarten Plättchen gleich sind.

```java
static boolean isGameOver(int[][] board) {
    // dein Code hier -- kein leeres Feld, und keine gleichen Nachbarn
}
```

Jedes Feld mit dem rechts daneben und dem darunter zu vergleichen genügt, um jedes
Nachbarpaar genau einmal zu erfassen. Überleg dir, warum links und oben zusätzlich
zu prüfen verschwendete Mühe wäre.

Dann die zweite Hälfte, der man schwerer widersteht falsch zu machen: Ein
Plättchen, das in eine Richtung frei verschmelzen kann, ist in einer anderen
vielleicht blockiert. Überzeug dich davon, dass die Nachbarprüfung oben sich für
die Richtung nicht interessiert, und dass das richtig so ist.

Bau zum Testen absichtlich ein volles Feld, indem du das Array in `main` von Hand
füllst, bevor die Schleife startet.

## Was du gelernt hast

- Ein Spielfeld als `int[][]`, und `board[row]` als ganze Zeile für eine Methode
- `%5d`, damit Spalten untereinander bleiben, wie groß die Zahlen auch werden
- Dass ein Terminal keinen einzelnen Tastendruck liefern kann, und was das kostet
- Zusammenschieben, verschmelzen, zusammenschieben, und warum ein Plättchen nur
  einmal verschmelzen darf
- Ein Spielfeld drehen, damit eine Operation alle vier Richtungen bedient
- Ein `switch`, das als Wert benutzt wird statt als Anweisung
- Ein Spielfeld kopieren statt umbenennen, und warum dieser Unterschied über das
  Spiel entscheidet
- *(optional)* Jedes Nachbarpaar genau einmal prüfen
